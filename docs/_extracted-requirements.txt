H&B Development Plan
System Name: H&B Service Group – Product & Platform
Here's a modular summary of the build plan:
Module 1 — Marketing Website
A CMS-driven public-facing site with the following pages and navigation: Home, Hire Staff, Find Work, Services, About, Contact, and Login. Two primary CTAs drive the entire site — "Hire Staff" and "Find Work".
Key pages include the Home Page (hero section, services overview, value proposition, social proof) and the Hire Staff Page (B2B lead generation form capturing company name, contact, staff type, location, dates, headcount, and notes). The Find Work Page targets freelancers with role types, benefits, and an Apply Now CTA.
Module 2 — Freelancer Registration & Onboarding
A 3-step flow: basic info (name, email, phone, location) → work type selection (Hospitality or Security) → security-specific compliance branch. Freelancers either upload an existing license or register interest in obtaining one.
Module 3 — Security Compliance
Handles license upload, license number, and expiry date. Statuses: Pending / Approved / Expired. Includes a separate flow for applicants without a license to register interest and be tracked internally.
Module 4 — Freelancer Portal
The core operational interface for workers, consisting of three sub-modules:
Dashboard — assigned jobs, submitted hours, invoice overview, status tracking
Time Tracking — per-assignment entries with start/end time, break, total hours, and notes. Status flow: Draft → Submitted → Approved → Rejected
Invoice Module — auto-generated from approved hours, PDF output, statuses: Draft / Approved / Paid
Module 5 — Admin Panel
Internal operations control center with: user management, onboarding validation, assignment creation & freelancer assignment, time approval, invoice generation, and data export (Excel/CSV). Also handles compliance controls — ID verification, KvK, VAT number, and security license validation.
Module 6 — Core Workflow Engine
The end-to-end operational process:
Freelancer applies → 2. H&B approves account → 3. License verified (if security) → 4. Freelancer assigned to job → 5. Hours submitted → 6. H&B approves hours → 7. Invoice auto-generated → 8. Manual payment processed
Module 7 — Phase Roadmap

3.3 What NOT to do — colour errors
⚙ DEVELOPER: Brief this list to yourself before implementing. These are the most common mistakes that will break the brand.
NEVER use white text on the gold CTA button — insufficient contrast ratio. Always use navy (#0D1B2A) text on gold.

4. CTA Strategy  (Call-To-Action)
⚙ DEVELOPER: CTA = the clickable buttons that direct visitors to take action. The current site has too many CTAs that look identical and say the same thing, causing decision paralysis and reducing conversions. The fix is simple: maximum two CTAs per section, always visually differentiated.
Core CTA rule — enforce everywhere
Maximum TWO CTAs per section. Always one filled (primary) and one outline (secondary).
NEVER three identical buttons side by side — this is currently happening and must be fixed.
NEVER use the same CTA label twice on the same page unless it is intentional repetition at the end of a long page.
Primary CTA = the main conversion action for that page's audience.
Secondary CTA = an alternative for visitors who are not yet ready to convert.
